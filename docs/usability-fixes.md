# 사용성 검토 반영 내역

기준: `songil-usability-review.md`와 참고용 `app.html` (2026-11-14).

후속 사용자 요청으로 버튼 동작을 다시 통합했다. 대기 중에는 말하기, 탐색·처리 중에는 같은 버튼이 그만이다. 별도 정지 버튼은 없고, 정지 후 다시 눌러 새 명령을 받는다. 아래의 탐색 중 음성 명령·별도 그만 및 좌우 질문 답변은 이전 적용 기록이며 현재 UI에서는 제공하지 않는다. 비슷한 두 후보는 알림 종료 5초 뒤 큰 쪽을 자동 선택한다.

추가 반영: `FE-희찬수정안-1457.md`. 자동 잡는 법은 손 안내가 시작된 뒤 한 번만 재생하며, 설명 캡처 여백·confidence 정의·실제 탐지 이름·대상 고정·유사 후보 좌우 선택·음성 종료 기록을 함께 적용했다.

## 초점 전환 추가 수정

- 서버 결과는 신뢰도 0.5 이상만 사용하며 실제 label을 name으로, label===target을 exact로 보관한다.
- 대상은 정확 일치 → 신뢰도 → 크기 순으로 선택한 뒤 고정한다. 1초 넘게 놓치기 전에는 멀리 있는 다른 대상으로 바꾸지 않는다. 15% 이내에서 바뀐 트랙 번호는 같은 물체로 이어 간다.
- 정확 일치 후보 둘이 1초 이상 유지되고 신뢰도 차이가 0.15 미만이면 좌우를 한 번 묻는다. 왼쪽·오른쪽·첫 번째·두 번째는 서버 해석 없이 처리한다. 질문 재생 후 5초간 답이 없으면 더 크게 보이는 쪽으로 안내한다.
- #dev에서 실제 이름·정확 일치 여부와 최근 음성 종료 이유 5개 및 호출 위치를 확인한다. 개발 모드에서는 콘솔에도 남긴다.

## 별도 백엔드 작업

이 저장소에는 `server.py`가 없으므로 다음은 반영하지 않았다.

- `ensure_words`의 전역 모델 잠금·동시 추론 및 기본 어휘 구성
- 서버 `/parse` 캐시의 만료·무효화 정책
- 백엔드의 `/app/`, `static/` 배포·정리 방침

서버가 `target`을 반영하고 `hazard` 또는 구형 `safety`를 반환하는지 실제 서버에서 확인해야 한다. 커스텀 prompt가 꺼진 서버에서는 기본 prompt.txt에도 대상 자체 확인과 손잡이 확인을 구분하는 confidence 정의가 필요하다.

## 검증 범위

버튼 접근성 렌더링, 서버 3회 실패·복구, 대기 요청 취소, 현재 위치 질의·사용자 완료 확인, Wake Lock 재요청·정리, 자동 설명 중 안내 유지, API 요청·제한 시간, 녹음·TTS 재사용과 기존 5초 무음 회귀 테스트를 실행한다. 타입 검사와 프로덕션 빌드를 함께 확인한다.

실기기 카메라·마이크 권한, TalkBack, 화면 잠금 정책, 실제 모델·TTS 서버 응답은 별도 현장 검증 대상이다.

## 계속 듣기 후속 변경

탐색 중 마이크 버튼은 그만 동작을 유지하면서 별도의 연속 음성 인식을 함께 실행한다. 손 안내·앱 음성·5초 무음 중에도 그만을 감지한다. 다른 명시적 명령은 앱 음성이 끝난 뒤 처리하며 일반 대화는 무시한다. 좌우 선택 질문도 연속 음성으로 답할 수 있다. 브라우저의 인식 종료·무음은 자동 재시작하고, 권한 거부·지원 불가·반복 오류는 수동 정지 대안을 알린다. 실제 모바일 브라우저의 마이크·오디오 동시 동작은 실기기 확인이 필요하다.

## 안드로이드 Chrome 음성 수정

그만해요·이제 그만·이전 인식 뒤에 붙은 중지 명령과 대체 인식 후보를 처리한다. 일시적 인식 오류는 영구 중단하지 않고 다시 연결하며, 15초간 결과가 없는 인식도 재시작한다. 권한 거부는 계속 재요청하지 않는다. 계속 듣기 오류는 물체 안내 화면을 unknown으로 바꾸지 않고 별도로 표시한다. #dev에 인식 상태·오류 코드·최근 인식 문장을 표시한다.

이미 실행 중인 인식은 안내 중에도 유지하되, 안내 재생 중 종료된 인식의 새 세션은 재생과 350ms 잔향이 끝난 뒤 시작하여 오디오 포커스 충돌을 줄인다. 첫 폰 방향은 발견 음성 뒤 최소 1.5초 간격으로 안내하며, 실패한 재생은 반복 제한에서 제외한다. 예기치 않은 오디오 일시정지는 즉시 재생 상태를 해제하고, 시작되지 않는 브라우저 음성은 4초 제한으로 다음 안내를 막지 않게 한다. 실기기 마이크·스피커 동시 동작은 현장 확인 대상이다.

## 음성 입력·안내 병렬 재생

녹음 파일과 서버 TTS Blob을 공용 AudioContext의 AudioBufferSourceNode로 재생한다. 시작 버튼에서 공용 컨텍스트를 활성화하고 안내음도 같은 컨텍스트를 사용한다. Web Audio 재생 중에는 음성 인식 시작·재시작을 기다리게 하지 않는다. 컨텍스트가 일시정지되면 같은 소스를 resume하여 재생 위치를 유지한다. 그만·안전 경고 등 명시적인 취소·우선순위는 기존대로 동작한다.

디코딩 버퍼는 최대 16개·16MB까지 캐시한다. 취소된 디코딩 결과는 재생하지 않으며 이벤트·소스는 작업 종료 시 정리한다. Web Audio 실패는 기존 미디어 요소, 이어 브라우저 음성으로 대체한다. 대체 경로에서만 인식 재시작을 출력 종료 후로 미룬다. #dev에서 web-audio/media-element/browser-tts/loading/idle 경로를 확인한다. Android Chrome 실기기의 오디오 정책과 에코는 현장 검증 대상이다.

## 최신: 15:53 수정안

FE-희찬수정안-1553.md에 따라 계속 듣기를 비활성화하고 버튼으로 한 번 듣는 방식으로 전환했다. 안내 중 버튼은 즉시 안내·효과음·요청을 멈춘 뒤 최대 6초 듣는다. 무음 5초나 오류는 멈춤을 유지하며 어떻게 잡아만 설명 후 재개한다. 완료는 사용자 확인만 사용하며 잡으셨군요. 안내를 마칠게요와 진동 후 대기로 돌아간다.

손 안내 단계는 가운데 0.5초 또는 손 0.5초로 잠근다. 좌우 가장자리 10%·놓침 때만 다시 조준하고, 안쪽 25~75% 복귀 시 손 안내로 돌아간다. 목표 위치 안내는 찾기당 한 번만 재생하며 기존 5초 무음은 유지한다. 손 안내 중 가운데 칸 유지 조건은 더 이상 적용하지 않는다.

날카로운 대상은 손잡이 확인 전 중앙 유도를 금지하고 즉시 설명 요청을 보낸다. 반대쪽 절반을 추정 칼날 구역으로 보아 0.3초 진입·최소 4초 반복·벗어남 해제 규칙으로 경고한다. 이 근사는 접촉이나 실제 칼날 위치를 확정하지 않는다. 관련 구조·현재 동작은 README와 status-frame-ui.md를 따른다. 앞의 계속 듣기 기록은 과거 동작이다.
