# 프론트엔드 구현 범위

| 요구사항 | 상태 | 구현과 한계 |
| --- | --- | --- |
| FR-1.1 | 부분 구현 | COCO 80종 내 탐지 결과를 화면·한국어 음성으로 안내. 모든 물체 인식은 지원하지 않음. 화면 첫 터치 후 음성 활성화. 0.6초 유지된 선택 물체를 안내하고 최소 5초 간격으로 발화. 마이크 인식 중에는 안내 중지. |
| FR-1.2 | 구현 | 모델이 cup/bowl로 분류한 후보에 한해 원본 영상 박스의 높이 ≥ 너비면 컵, 너비가 더 길면 보울. 이는 요구사항에 따른 휴리스틱이며 기울기·촬영 각도·가림에 따라 실제 종류와 다를 수 있음. |
| FR-1.3 | 구현 | MediaPipe Hand Landmarker로 최대 손 2개, 각 21개 관절점 표시. 엄지 끝(4)·검지 끝(8)의 화면 픽셀 좌표 표시. 왼손/오른손 대신 손 번호 표시. 손 결과는 보간·가상 생성하지 않으며 오래된 결과는 제거. |
| FR-1.4 | 부분 구현 | 선택 물체에 가까운 손의 두 손가락 끝에서 물체 박스까지의 화면상 최단 간격과 이동 방향을 화면·음성으로 안내. 간격 %는 화면 대각선 대비 비율. 미터 단위 실제 거리·깊이·접촉은 추정하지 않음. |
| FR-1.5 | 구현 | 카메라를 화면에 맞게 자른 뒤 실제 보이는 탐지 박스 면적이 가장 큰 물체 하나만 표시·안내. 위치와 관계없음. 선택 물체는 민트색. 기존 상자는 짧은 탐지 끊김에 최대 650ms 유지하되 이때 음성·손 안내는 중지. |
| FR-2.1 | 미구현 | 실제 잡을 부위를 추정할 모델·그립 포인트 정의가 없음. 3초 유지되거나 박스 중심이라는 이유만으로 그립 포인트를 생성하지 않음. |
| FR-2.2 | 미구현 | 그립 포인트가 없으므로 거리·접촉 계산을 수행하지 않음. FR-1.4는 물체 박스까지의 2D 간격이며 이 항목을 대체하지 않음. |
| FR-2.3 | 미구현 | 그립 성공 기준과 실제 접촉을 검증할 정보가 없어 성공 발화 없음. |
| FR-2.4 | 미구현 | 성공 판정에 의존하므로 인식 정지 상태로 전환하지 않음. |
| FR-2.5 | 미구현 | 성공 후 정지 상태가 없어 재시작 전환 없음. 현재 화면 터치는 음성 안내 활성화에 사용. |

## 실행·검증

`npm.cmd run dev -- --mode https --port 5173` 실행 후 같은 Wi-Fi에서 Network HTTPS 주소로 접속하고 카메라 권한을 허용한다. 화면을 터치하면 음성 안내가 활성화된다. 음성 인식 버튼은 말한 내용을 텍스트로 표시한다.

영상은 백엔드로 전송하지 않는다. 두 모델은 같은 작업 스레드에서 순차 추론하며 동시에 처리하는 프레임은 하나, 최대 초당 5회다. 화면을 벗어난 물체·손가락은 안내 대상으로 선택하지 않는다.

손 모델: https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task

공식 사용법: https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker?tab=Web

검증: TypeScript·Vite 빌드, 실제 Chrome 워커에서 Google 공개 `right_hands.jpg`의 손 2개·관절점 각 21개·유효한 엄지/검지 좌표 확인. 좌표 투영·화면 잘림·방향·2D 겹침 계산 검증. 모바일 카메라 실환경에서 모델 정확도, 가려진 손, 음성 재생 정책, 발열·속도는 추가 확인이 필요하다.
